# Фермерский маркетплейс — приложение хозяйств и серверная часть

Платформа прямой продажи мяса в Казахстане: хозяйство выставляет тушу, покупатель берёт её целиком
или половиной, деньги идут через эскроу, каждый этап подтверждается фотографиями.

Этот репозиторий — **приложение для хозяйств (Flutter) и вся серверная часть платформы**.
Приложение покупателя и сайт лежат отдельно.

## Что внутри

| | |
|---|---|
| `lib/` | приложение хозяйства: витрина, лоты, заказы по четырём шагам, онлайн-касса, справка |
| `packages/et_core` | предметная область на чистом Dart: деньги, доли туши, статусы, поиск по справке. Ни Firebase, ни Flutter — 96 тестов без единого мока |
| `packages/et_data` | репозитории Firestore |
| `packages/et_ui` | дизайн-система: карточки, пустые состояния, скелетоны, светлая и тёмная темы |
| `functions/` | 22 Cloud Functions: заказы, платежи, выплаты, фискальные чеки, уведомления, расписания |
| `firestore.rules`, `storage.rules` | правила доступа — 185 и 36 тестов |

## Что здесь интересного инженерно

**Модель туши.** Единица товара — одно животное, которое продаётся целиком или пополам. Отсюда
целочисленные тенге, пересчёт после контрольного взвешивания и возврат разницы на ту же карту.
Вся арифметика в `et_core` и покрыта тестами: ошибка в ней не видна глазом, а всплывает налоговым
расхождением.

**Двухстадийная оплата.** Деньги блокируются на карте при оформлении и списываются, когда хозяйство
приняло заказ. Выплата идёт тремя частями — 50 % при подтверждении, 25 % при отгрузке, 25 % после
получения. Платёжная ось заказа намеренно отделена от оси исполнения: деньги можно вернуть по
доставленному заказу, а полностью оплаченный заказ может ждать подтверждения.

**Мультиарендная фискализация.** Чек выбивается кассой того хозяйства, чьё мясо продано, и выходит
под его БИН: площадка — не продавец. Ключ интеграции один на всех, пароль — у каждой кассы свой.
Модуль `functions/rekassa.js` самостоятельный, 35 проверок гоняются без сети и без ключей.

**Правила как защита, а не как украшение.** Доступ к онлайн-кассе не читает никто из клиентов,
включая самого владельца и администратора: это ключи, которыми выбиваются налоговые документы.
Проверяется тестом, чтобы ослабить это потом молча не вышло.

## Что убрано из этой копии

Репозиторий — публичная копия рабочего проекта. Из него вырезаны данные заказчика и всё
чувствительное: реквизиты юридического лица, телефоны и почта, идентификаторы проекта Firebase
и платёжного мерчанта, адреса серверов, боевые идентификаторы пользователей, доступы к онлайн-кассе,
внутренние планы и юридические документы. Ключи подписи приложений и файлы окружения в репозиторий
никогда не попадали — они под `.gitignore` с первого дня.

История коммитов не переносилась намеренно: один коммит вместо неё, чтобы ничто не уехало прошлым.
Поэтому проект **не собирается как есть** — нужны свои `google-services.json`, `firebase_options.dart`
и `.env` (рядом лежат файлы `.example`).

Права на код принадлежат заказчику. Выложено как портфолио.
